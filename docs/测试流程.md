# 测试流程与验收清单

本文档用于按功能逐项验证当前实现。所有步骤均在本地执行，不需要外部模型或网络服务。

分两部分：`mock` 模式（浏览器本地数据，用于快速验证交互）与 `api` 模式（FastAPI + SQLite，用于验证落库与接口）。

## 一、环境准备

### 1. 启动后端



```
cd D:\learn\youli\consumer-protection-agent\backend
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --port 8000
```

预期：控制台出现 `Uvicorn running on http://127.0.0.1:8000`。

浏览器打开 `http://127.0.0.1:8000/docs` 可看到全部接口（Swagger 页面，无需额外工具）。

### 2. 启动前端



```
cd D:\learn\youli\consumer-protection-agent\frontend
npm.cmd run dev
```

预期：控制台输出 `Local: http://127.0.0.1:5173/`，浏览器打开该地址进入案件中心。

### 3. 切换数据模式

前端默认 `mock` 模式。切换到后端联调时，在 `frontend` 目录新建 `.env.local`：



```
VITE_DATA_MODE=api
VITE_API_BASE_URL=/api
```

修改后需**重启** `npm run dev`（环境变量只在启动时读取）。

切回演示：把 `VITE_DATA_MODE` 改回 `mock` 或删除该文件，再重启。

### 4. 自动化验证



```
# 后端单元测试（输出走 stderr，PowerShell 报 NativeCommandError 属正常，以末尾 OK 为准）
cd D:\learn\youli\consumer-protection-agent\backend
.\.venv\Scripts\python.exe -m unittest discover -s tests -v

# 前端生产构建
cd D:\learn\youli\consumer-protection-agent\frontend
npm.cmd run build
```

预期：`Ran 38 tests ... OK`；构建输出 `✓ built in ...`，无报错。

## 五、查看后端数据库内容

### 数据库类型

当前**不是** MySQL，而是 **SQLite**：单文件数据库，无需安装数据库服务、无需下载任何东西。

配置见 `backend/app/database.py`：默认 `sqlite:///backend/youli.db`，可用环境变量 `DATABASE_URL` 覆盖。

文件位置：`backend/youli.db`（已被 `.gitignore` 的 `*.db` 排除，不进版本库）。

### 注意事项



1. **mock 模式不写数据库**：数据只在浏览器 `localStorage`。想看库内容必须先切 `api` 模式并新建案件。

   清除 mock 数据：浏览器控制台执行 `localStorage.removeItem('youli.cases.v1')` 后刷新。

2. **新字段只在新建案件时写入**：`youli.db` 中 2026-11-12 创建的 4 条旧记录是旧版本结构，不含 `tradeTime`、`goalPlan`、`complaintAttachments`、`resolution`、`followups` 等字段；新建案件才会有完整字段。读取旧记录时前端按 "待补充" 处理，不影响使用。

3. **上传的文件不在数据库里**：文件存于 `backend/uploads/`，库中只记录元信息与 `storageName`。

## 六、当前实现的已知限制



1. 分析、法律依据、沟通建议、投诉草稿均为**关键词匹配 + 模板拼接**，不接模型、不做 RAG，界面已标注 "模拟 / 待核验"。

2. 不向任何外部平台提交投诉，草稿仅保存在本地案件。

3. 渠道推荐顺序、诉求合理性判断、证据证明力评估属 Agent 模块，当前只提供静态清单与人工核对。

4. 金额以 `float` 存储，未改 `Decimal`；金额公式自动计算未做。

5. 材料仅图片可在线预览，PDF/DOCX/TXT 走下载。

6. 无账户体系与权限隔离；个人资料仅存浏览器本地，未上传后端。

7. 案件阶段由动作直接设定（生成分析即「分析中」、记录回复即「协商中」），尚未按证据是否齐全、商家是否答复、有无受理编号等事实推导，「处理进度」只能反映已执行的动作。

8. 材料内容未解析：附件中的文字不进入分析与证据核验，`content_verified` 恒为 false，界面统一标注「已上传，未核验」。
