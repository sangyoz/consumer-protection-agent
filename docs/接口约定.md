# 前后端接口约定

基础路径 `/api`，除文件上传外请求使用 JSON。当前按单用户、本地开发设计。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | /health | 服务状态、当前 Agent 模式 |
| GET | /cases | 案件列表 |
| POST | /cases | 创建案件 |
| GET | /cases/{id} | 获取完整案件 |
| POST | /cases/{id}/analysis | 生成演示分析并保存 |
| POST | /cases/{id}/messages | 记录商家回复，返回含演示建议的案件 |
| POST | /cases/{id}/complaint | 生成投诉草稿并保存 |
| POST | /cases/{id}/materials | 上传材料，multipart 的字段名为 files |
| POST | /cases/{id}/progress | 添加跟进记录并可更新状态 |

创建案件输入：`title`、`summary`（必填）、`merchant`、`amount`（元）、`goal`。金额使用非负值；后续金额计算建议改用后端 Decimal 并约定精度。

沟通输入：`{ "content": "商家回复原文" }`。

跟进输入：`{ "note": "新的处理反馈", "stage": "following", "confirmed": false }`。`stage` 可为 null，表示保持当前状态。改为 `resolved` 时，必须提供 `confirmed: true` 表示用户确认诉求实际履行。

除列表与健康检查外，成功操作统一返回完整案件：

```text
id, title, summary, merchant, amount, goal, stage,
createdAt, updatedAt,
analysis: null | { summary, category, missing[], rights, legal, strategy, script },
messages: [{ id, role, content, createdAt }],
materials: [{ id, name, size, status, storageName? }],
complaint: string,
timeline: [{ id, text, createdAt }]
```

法律结构：`{ name, explanation, source, verified }`。当前 `verified` 恒为 false，禁止将模拟结果展示为已核验法律。后续可扩展法律版本、生效时间和适用条件等字段。

消息角色：`merchant` 是用户录入的商家原文，`assistant` 是系统输出。后续可扩展 `user`、`system`。

阶段：`collecting` 待完善、`analyzing` 分析中、`negotiating` 协商中、`complaining` 投诉中、`following` 待履行、`resolved` 已解决。`complaining` 只表示正在准备或处理投诉，不表示已向真实平台提交。

材料状态：`demo` 示例记录、`metadata` 仅文件元信息、`uploaded` 文件已存储但未解析。当前不提供附件下载或公开静态目录。

错误：业务错误使用 HTTP 400/404/409/413，返回 `{ "detail": "错误说明" }`；字段校验失败为 422。

真实 AI、SSE 事件和外部提交接口尚未实现，接入时先共同确定事件结构与用户确认节点。
